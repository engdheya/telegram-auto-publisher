# Telegram Auto Publisher — USER_GUIDE.md

> دليل استخدام لوحة التحكم خطوة بخطوة (عربي) + لوحة AR/EN.

---

## 0. الجولة السريعة (Quick Start — 6 خطوات)

1. **سجّل الدخول** → `http://<host>:5173` باسم المستخدم وكلمة المرور.
2. **اربط حساب تيليجرام**: `حساب تيليجرام` → أدخل API ID / API Hash (من my.telegram.org) والرقم الدولي → *إرسال رمز التحقق* → أدخل الرمز → (كلمة مرور 2FA إن وُجدت).
   - بعد النجاح تظهر: **متصل** و`auth_state=CONNECTED` و**جلسة مشفّرة محفوظة**.
3. **أضف مصدرًا**: `قنوات المصدر` → *إضافة مصدر* → الاسم + `@channel_username` → *حفظ* → اضغط **اختبار الوصول** (يسجّل `baseline_message_id`) → **بدأ المراقبة**.
4. **أضف وجهة**: `قنوات الوجهة` → *إضافة وجهة* → *حفظ* → **تحقق** (يجب أن تظهر `VERIFIED`) → جرّب **اختبار النشر**.
5. **أنشئ مسارًا**: `مسارات النشر` → *إنشاء مسار* → إما مسار مفرد (مصدر + وجهة + قواعد) أو **ربط متعدد N×M** (اختر عدة مصادر وعدة وجهات ⇒ تُنشأ كل الأزواج).
6. **راقب**: `لوحة المؤشرات` للمؤشرات، `سجل المنشورات` للأحداث، `إدارة الطابور` للمهام، `السجلات` للأخطاء.

> بعد كل خطوة، راجع `السجلات` — كل عملية تُسجَّل بفاعلها ونتيجتها.

## 1. صفحة الدخول (Login)

| العنصر | الوظيفة |
|---|---|
| اسم المستخدم / كلمة المرور | مصادقة ضد `/api/v1/auth/login` (JWT) |
| زر تبديل اللغة | يبدّل AR/EN فورًا (RTL/LTR) |
| رسالة الخطأ الحمراء | تعرض **سبب الرفض الفعلي** من الـBackend |

- الجلسة تُحفظ في `localStorage` وتُبطَل عند 401 أو بعد انتهاء المدة.
- محاولة الوصول لأي صفحة بدون جلسة تُعيدك إلى `/login`.

---

## 2. لوحة المؤشرات (Dashboard)

**يعرض مباشرة من قاعدة البيانات (تحديث كل 15 ثانية):**
- حالة اتصال تيليجرام + اسم الحساب + `auth_state`.
- حالة العامل (Online/Standby) + آخر نبضة.
- سلامة قاعدة البيانات: `journal_mode`, `FK`, عدد الجداول.
- عدد المصادر (والمفعّل منها)، الوجهات (والموثّقة)، المسارات النشطة.
- المنشورات المستلمة، الناجحة، الفاشلة، المنتظرة، قيد التنفيذ، المتخطاة، **UNKNOWN**.
- آخر 10 عمليات من سجل التدقيق.

> **UNKNOWN > 0** تعني: هناك مهام تحتاج قرارًا. اذهب إلى `إدارة الطابور` → تبويب *تحتاج مراجعة* → **مصالحة**.

## 3. حساب تيليجرام (Telegram Account)

| العنصر | الوظيفة |
|---|---|
| حالة الاتصال | متصل/غير متصل + `auth_state` |
| بيانات الحساب | الاسم، `@username`، الرقم **مقنّع** (`+967******000`) |
| API ID / API Hash | يُعرض API ID فقط، والـHash كـ"مخزَّن مشفرًا ✓" — **لا يُعرض أبدًا** |
| بدء الربط | إدخال البيانات + إرسال OTP |
| تأكيد الرمز | `verify-code` (قد يطلب كلمة مرور 2FA) |
| إعادة الاتصال | إعادة فتح الجلسة المحفوظة + **التقاط الرسائل الفائتة** |
| إعادة الاتصال التلقائية | Toggle يُحفظ في قاعدة البيانات |
| تسجيل الخروج | يحذف الجلسة ويُلغي الربط (تأكيد مطلوب) |

> إدارة الحساب متاحة لصلاحية **Admin** فقط؛ المشغّل يرى الحالة بدون أزرار تعديل.

## 4. قنوات المصدر (Sources)

| الزر | ما يفعله فعليًا |
|---|---|
| إضافة مصدر | `POST /sources` — يقبل `@username` أو رابط `t.me` أو Peer ID رقمي |
| اختبار الوصول | `POST /sources/{id}/verify` — يستدعي Telethon ويحدّث `monitoring_status` و`last_error` |
| بدأ المراقبة | `POST /sources/{id}/start` — **يسجّل `baseline_message_id`** (لا أرشيف) |
| إيقاف | `POST /sources/{id}/stop` — الحالة `PAUSED` |
| تفعيل (Toggle) | `PATCH /sources/{id}` |
| تعديل / حذف | `PATCH` / `DELETE` (الحذف يحذف مساراته، ويسجل تحذيرًا) |

**أعمدة الجدول:** القناة، المعرّف، الحالة، `baseline / last`، آخر معالجة، التفعيل، الإجراءات.
**شارة `noforwards`** تظهر إذا كان المحتوى محميًا (سيُسجَّل `SKIPPED` عند النشر).

---

## 5. قنوات الوجهة (Targets)

| الزر | ما يفعله |
|---|---|
| تحقق | `POST /targets/{id}/verify` — يضبط `permission_status` و`can_post_messages/media` |
| اختبار النشر | `POST /targets/{id}/test-publish` — **يرسل رسالة حقيقية** ويعرض رد تيليجرام الحرفي |
| تفعيل / تعديل / حذف | نفس نمط المصادر |

> اذا ظهر `ChatWriteForbiddenError` أو `INSUFFICIENT_PERMISSIONS`: الحساب المربوط ليس لديه صلاحية نشر في تلك القناة — أضفه كمسؤول (Admin) في القناة أولًا.

## 6. مسارات النشر (Routes) — قلب النظام

### 6.1 مسار مفرد (1→1)
`إنشاء مسار` → التبويب *مسار واحد* → الاسم + المصدر + الوجهة + الأولوية + الحالة + القواعد → *إنشاء المسار*.

### 6.2 ربط متعدد N×M
`إنشاء مسار` → *ربط متعدد N×M* → اختر عدة مصادر وعدة وجهات → يظهر عدّاد `سيتم إنشاء N مسارًا` → *إنشاء N مسار*.
- يُنشئ كل الأزواج في **طلب واحد ذرّي**؛ الأزواج الموجودة تُتخطّى دون خطأ.
- مثال: مصدران × 3 وجهات = 6 مسارات.

### 6.3 قواعد التصفية (Filters)
| القاعدة | التأثير |
|---|---|
| أنواع المحتوى المسموحة | أي نوع غير محدد ⇒ `SKIPPED` |
| كلمات للتضمين | يجب أن يحتوي النص على واحدة منها |
| كلمات للاستبعاد | إن وُجدت ⇒ `SKIPPED` |
| أدنى/أقصى طول نص | خارج النطاق ⇒ `SKIPPED` |
| امتدادات مسموحة | للملفات؛ فارغ = الكل |
| نص قبل / بعد | يُلصق بالنص المنشور |
| توقيع الوجهة | يضاف في نهاية المنشور |
| حذف الروابط | يحذف الـURLs قبل النشر |

### 6.4 التحكم في المسار
- **Toggle** = تبديل مستقل (`POST /routes/{id}/toggle`) — تعطيل مسار لا يؤثر على أي مسار آخر.
- **حذف** = يحذف هذا المسار فقط (المصادر/الوجهات تبقى).
- القواعد تُحفظ من زر *القواعد* داخل المودال (`PATCH /routes/{id}` مع `filters`).

## 7. سجل المنشورات (Messages / Publishing History)

- كل حدث مستلم قابل للتوسيع (اضغط الصف).
- يعرض: النص الأصلي، الوسائط (النوع/الحجم/الأبعاد/الحالة)، وكل **مهمة نشر لكل وجهة**.
- شارات الحالة: `QUEUED/PROCESSING/PUBLISHED/RETRY_WAIT/SKIPPED/FAILED/UNKNOWN`.
- **معرّف الرسالة في الوجهة** يظهر بعد النشر (`target msg #900`).
- زر **إعادة محاولة** يظهر للمهام `FAILED`/`RETRY_WAIT` فقط.
- المهام `SKIPPED` بسبب حماية المحتوى لا تعرض زر إعادة (لأن الإعادة لن تنجح — احترامًا للحماية).
- تصفية: المصدر، نوع المحتوى، بحث نصي.

---

## 8. إدارة الطابور (Queue Management)

| التبويب | المعنى |
|---|---|
| الكل / منتظرة / قيد التنفيذ / انتظار إعادة / فاشلة / **تحتاج مراجعة** / متخطاة / ناجحة | تصفية حسب الحالة (مع عدّاد لكل حالة) |

**الإجراءات:**
- **إعادة محاولة** (`FAILED`/`SKIPPED`/`RETRY_WAIT`) ⇒ تعود `QUEUED` مع إعادة ضبط العدّاد.
- **مصالحة** (`UNKNOWN` فقط) ⇒ يفحص آخر رسائل الوجهة: إن وُجد المنشور ⇒ `PUBLISHED` (بلا إعادة نشر)، وإلا يُعاد للطابور.
- **إلغاء** (ليس `PUBLISHED`/`PROCESSING`) ⇒ `SKIPPED` مع سبب `CANCELLED_BY_OPERATOR`.
- توسيع المهمة يعرض: النص بعد التصفية، آخر خطأ، سبب التخطي/UNKNOWN، و**كل المحاولات** (العامل، البداية/النهاية، النتيجة، رمز الخطأ).

> التحديث تلقائي كل 10 ثوانٍ.

---

## 9. السجلات (Logs)

- تصفية بالمستوى (`INFO/WARNING/ERROR/CRITICAL`) والفئة (`AUTH/TELEGRAM/SOURCE/TARGET/ROUTE/INGESTION/PUBLISHER/QUEUE/BACKUP/SYSTEM/SECURITY`) وبحث نصي.
- زر **JSON** يفتح الدرج الخام (details, entity, ip, timestamps).
- لا تُسجَّل كلمات المرور ولا رموز التحقق ولا الـAPI Hash (Redaction).

## 10. الإعدادات (Settings)

| القسم | ما يمكن فعله |
|---|---|
| إعدادات النظام | اللغة الافتراضية، محاولات الإعادة، الانتظار الأساسي/الأقصى، نافذة الألبوم، مدة احتفاظ الوسائط، مدة الجلسة، نسخة أمان قبل الاستعادة |
| تغيير كلمة المرور | يتطلب الحالية + تأكيد الجديدة (8 أحرف على الأقل) ⇒ JWT جديد وإبطال الجلسات الأخرى |
| فحص سلامة قاعدة البيانات | `integrity_check`, `foreign_key_check`, `journal_mode`, الجداول المفقودة |
| إدارة المستخدمين (Admin) | إضافة مستخدم بدور operator/admin ولغة مفضلة + جدول المستخدمين |
| النسخ الاحتياطي (Admin) | إنشاء نسخة الآن (بتسمية اختيارية)، تنزيل `.db`، استعادة (بتأكيد + نسخة أمان تلقائية) |

> المشغّل (Operator) يرى كل شيء لكن أزرار التعديل/النسخ معطّلة، وتظهر له رسالة "غير مصرّح".

---

## 11. سيناريوهات يومية

| الحالة | ما تفعله |
|---|---|
| منشور لم يصل للوجهة | Messages → ابحث عن الحدث → راجع `last_error` → Retry |
| مهمة UNKNOWN بعد إعادة تشغيل | Queue → تحتاج مراجعة → **مصالحة** |
| مصدر متوقف عن المراقبة | Sources → اختبار الوصول ثم **بدأ المراقبة** |
| وجهة فشلت صلاحياتها | Targets → تحقق → راجع صلاحيات الحساب في القناة |
| نسخ احتياطي قبل ترقية | Settings → إنشاء نسخة الآن بتسمية `before_upgrade` |
| إعادة ربط حساب | Telegram → تسجيل الخروج → ربط من جديد |
| تغيير لغة الواجهة | زر اللغة في الشريط الجانبي (يُحفظ تفضيلك) |

---

## 12. ما لا يفعله النظام (بصراحة)

- لا ينشر منشورات قديمة (لا أرشيف).
- لا يعيد نشر التعديلات ولا يحذف من الوجهة عند حذف الأصل.
- لا يتجاوز حماية `noforwards`.
- لا يضمن "مرة واحدة فقط" بشكل مطلق — استخدم المصالحة عند UNKNOWN.
- لا ينشئ API ID/Hash نيابة عنك.
